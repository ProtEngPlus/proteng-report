# ทะเบียนสถานะของ backlog

บันทึกนี้เป็นที่เดียวที่บอกว่างานแต่ละข้อเสร็จแล้วหรือยังค้าง และผูกกับวัตถุประสงค์ข้อไหน
ใน `overview.md` ไฟล์อื่นไม่ต้องบอกสถานะซ้ำ ถ้าสถานะเปลี่ยนให้แก้ที่นี่ก่อน
สถานะทั้งหมดเป็นของวันที่ 2026-11-16 และนับเฉพาะงานที่ merge เข้า branch `dev` แล้วว่าเสร็จ

วิธีใช้กับรายงานคือ แถวที่สถานะเป็น "เสร็จแล้ว" คือผลงานของภาคการศึกษาที่ 1 จึงใช้ในหัวข้อ
Timeline ของภาคการศึกษาที่ 1 ส่วนแถวที่สถานะเป็น "ยังไม่ได้ทำ" คือเนื้องานของภาคการศึกษาที่ 2
จึงใช้ในหัวข้อ Planned Work เท่านั้น ห้ามหยิบแถวที่เสร็จแล้วไปเขียนเป็นแผนของภาคการศึกษาที่ 2

## 2. งาน production-readiness

รายการชุดนี้คือช่องโหว่และจุดเปราะที่ทีมตรวจพบตอนรับช่วงต่อระบบ ซึ่งทีมเรียกรวมว่ารายการ BLB
งานที่ทีมเจอเองระหว่างพัฒนา feature ของปีนี้ไม่นับเป็น BLB รายการเต็มอยู่ใน
`manual-guides-2023/resources-2026/plan/bug-details.md` และ `explanation/known-issues.md`
ซึ่งอยู่ใน repo ส่วนตัวของทีม ตารางนี้จึงคัดมาเฉพาะข้อที่มีผลกับเนื้อหาของรายงาน

| งาน | วัตถุประสงค์ | สถานะ |
| --- | --- | --- |

ไม่ใช่งานที่เหลือของภาคการศึกษาที่ 2

## 3. ที่ยังต้องเติม

สามข้อนี้เป็นช่องว่างของทะเบียนนี้เอง ไม่ใช่งานของโครงงาน

ข้อแรกคือรหัส BLB ของแต่ละแถวในหัวข้อ 2 ซึ่งยังไม่ได้คัดมา เพราะรหัสอยู่ใน
`bug-details.md` ใน repo ส่วนตัว ถ้าต้องอ้างรหัสในรายงานหรือจะนับว่าปิดครบกี่ข้อแล้ว
ต้องคัดรายการทั้งชุดมาลงที่นี่ก่อน

ข้อที่สองคือเกณฑ์ของวัตถุประสงค์ข้อ 3 ที่เขียนถึงการเพิ่มการตรวจสิทธิ์เจ้าของทรัพยากร
ในเส้นทาง API ที่ยังขาดอยู่ ซึ่งไม่มีบันทึกรองรับในไฟล์ใดของ repo นี้ จึงยังไม่มีแถวในตาราง
ต้องยืนยันว่ามีงานข้อนี้จริงและกระทบเส้นทางใดบ้าง หรือไม่เช่นนั้นให้ตัดออกจากเกณฑ์

ข้อที่สามคือเจ้าของงานของภาคการศึกษาที่ 2 ซึ่งรอทีมตกลงร่างการแบ่งงาน
